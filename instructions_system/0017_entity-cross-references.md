title: entity-cross-references
trigger: when writing or editing any free-text field on a kb entity (Note/Todo/Goal/Journal body, description, notes) that mentions another kb record, by name or in passing

Refer to another kb record inline, within any free-text field, as TYPE:ID (e.g. `Todo:102`, `Goal:34`, `Note:98`) rather than describing it only in prose -- this is the same TYPE:ID form `kb link add` already accepts, addressed directly against a live entity, not a separate syntax to learn. Any entity supporting this auto-detects every such reference in its own free-text fields and creates the corresponding link automatically, so a reference written this way becomes durable, traversable graph structure with no separate linking step, and updates itself when the reference is edited or removed. Prefer this over `kb link add` for a bare "this record is related to that one" mention; reach for `kb link add` only when the relation itself carries meaning beyond mere mention (a typed label such as "tracked-by" or "blocks", read strictly in one direction).

Place each reference inline in the body prose, at the exact point where the related record is relevant, written the same way a wiki article links a term the first time it is mentioned -- not only collected in a trailing "Key sources"/"See also" list at the end. A parenthetical or clause that already names another record in passing (e.g. "the Fable/Mythos episode, see separate note") must spell that record as TYPE:ID at that point in the sentence, since that is the reference an auto-detecting reader or the auto-linker actually needs; a references section at the bottom is a supplement for entities not otherwise woven into the prose, never a substitute for inline placement.

Before submitting any such write, re-read the just-written text specifically hunting for a record mentioned by name/description without its TYPE:ID token -- this is a required pre-submit check, not a style preference to apply when convenient, because a body composed under normal writing attention reliably drifts into plain prose mentions unless explicitly checked against this rule at write time.
